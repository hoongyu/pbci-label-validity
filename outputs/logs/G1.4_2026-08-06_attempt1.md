## The fitter was validated before it was trusted, and it was wrong first

`analysis.md` §2 specifies crossed random effects — subject and session are
separate grouping factors, since every subject sees all three sessions.
statsmodels' natural idiom (`groups=subject`) can only *nest*, which would
estimate session-within-subject and silently answer a different question while
returning plausible-looking numbers. The crossed form is built with a single
dummy group plus explicit variance components.

Because that idiom is easy to get subtly wrong, `--simulate` generates data with
known variances and checks the estimates land near them. **It failed on the
first run**, and the failure was real: every variance component came back ~40×
too large while the residual was correct.

| component | true | first attempt | after fix |
|---|---|---|---|
| subject intercept | 100.0 | 4115.58 | 101.64 |
| subject slope | 25.0 | 1210.72 | 29.90 |
| session | 16.0 | 1246.67 | 30.79 |
| residual | 36.0 | 40.49 | 40.49 |

The cause: `fit.vcomp` is already in the outcome's variance units in this
statsmodels version, and I had multiplied by `fit.scale` on the documented
description that variance parameters are expressed relative to the residual
variance — which holds for `cov_re` but not for `vcomp` here. Multiplying
inflated every component by `scale` (~40 on this data) while leaving the
residual untouched, so nothing in the output looked wrong.

Had this shipped, the H1b decision would have been made on numbers 40× too
large. The decision would coincidentally have come out the same way — the CI
still excludes zero — but the reported variance components, the ICC and any
downstream effect size would all have been wrong. A zero-slope-variance control
is also included and returns 1.89 (≈0), so the rule can fire toward the pivot
and not only away from it.

Session variance is judged loosely in the validation (3 levels is barely
identifiable) and its estimate should be treated as indicative only. Note
N-Back's session CI has a lower bound of 0.02 — effectively at the boundary.

## What this means alongside G1.2

G1.4 is the gate that could have ended the original hypotheses, and it did not:
subjects genuinely differ in how their subjective effort tracks the nominal
difficulty label, in both tasks, with roughly 44–48% of RSME variance sitting
between subjects. The Study 2 machinery has a basis.

That is independent of the G1.2 fork and does not resolve it. G1.2 concerns
whether **EEG** tracks the label; G1.4 concerns whether **people differ** in how
their subjective report tracks it. Both can be true, and on this data both are.
