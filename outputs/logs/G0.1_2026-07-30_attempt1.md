- **Fresh environment build: FAIL.** Two independent defects.

  1. Lockfile encoding. The file was UTF-16 LE with BOM (PowerShell `>`
     redirect artifact). UTF-8 decoding raises
     `UnicodeDecodeError: 'utf-8' codec can't decode byte 0xff in position 0`.
     `uv` tolerates it; `pip` and any plain UTF-8 reader do not.

  2. Unresolvable torch pin. Fresh venv + `uv pip install -r
     env/requirements.lock` exited 1 in 1.4 s:

     ```
     × No solution found when resolving dependencies:
     ╰─▶ Because there is no version of torch==2.13.0+cpu and you require
         torch==2.13.0+cpu, we can conclude that your requirements are
         unsatisfiable.
     ```

     `+cpu` is a local version published only by
     `https://download.pytorch.org/whl/cpu`. Adding that index alone does not
     fix it — uv's default index strategy then fails on `certifi==2026.7.22`,
     which the PyTorch index also carries at a lower version:

     ```
     × No solution found when resolving dependencies:
     ╰─▶ Because there is no version of certifi==2026.7.22 ...
     hint: `certifi` was found on https://download.pytorch.org/whl/cpu, but
     not at the requested version ... use `--index-strategy
     unsafe-best-match` ...
     ```

     Resolution succeeds only with `--extra-index-url` **and**
     `--index-strategy unsafe-best-match`. Neither directive can be expressed
     inside a requirements file, so the lockfile cannot be made
     self-contained on this path. This also fails G4.1.
